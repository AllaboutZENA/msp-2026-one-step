# 학생 인터뷰 · 사용성 테스트 진행 질문지

관련 Issue: [#3 학생의 과제 관리 불편과 MVP 요구사항 확인](https://github.com/AllaboutZENA/msp-2026-one-step/issues/3) · 요구사항 [Requirements](../wiki/Requirements.md) · 기록표 [observation-sheet.md](observation-sheet.md) · 종합 [synthesis.md](synthesis.md)

시간이 부족하면 1인 10분짜리 [간소화 버전](lite-guide.md)(A3 + 필수 과제 B1–B4 + C4·C5)으로 진행합니다.

한 명당 약 25분이 걸립니다. 순서는 **A 인터뷰(8분) → B 앱 사용 과제(12분) → C 사후 질문(5분)**입니다. 결과는 실제로 진행한 내용만 기록합니다. 응답이나 수치를 지어내지 않습니다.

## 목적

1. **문제 가설 확인**: 마감일만 적어 두면 남은 작업을 파악하기 어렵다는 가설이 맞는지 확인합니다.
   - H1: 마감일만으로는 남은 작업량을 알기 어렵다.
   - H2: 큰 과제를 작은 단계로 나누는 습관이나 필요가 있다.
   - H3: 마감 하루 전 알림이 적절한 시점이다.
2. **사용성 확인**: 과제 등록 → 세부 작업 3개 추가 → 1개 완료 → 마감 확인 흐름을 도움 없이 할 수 있는지 봅니다. 완료 여부, 걸린 시간, 헷갈린 지점을 기록합니다.
3. **개선 근거 확보**: 심각도와 빈도가 높은 문제를 11–13주차 개선 Issue로 만듭니다.

## 대상과 모집

- 여러 과목의 과제를 동시에 관리하는 대학생 3–5명. 가능하면 학년과 전공 계열을 섞습니다.
- 팀원과 친한 친구만으로 구성하지 않습니다. 이 앱을 처음 보는 사람이어야 합니다.
- 이름, 학번, 연락처는 기록하지 않습니다. 참가자는 P1–P5 코드로만 적습니다.

## 준비물과 역할

| 항목 | 내용 |
| --- | --- |
| 진행자 | 질문을 읽고 과제를 안내합니다. 정답을 알려 주지 않습니다. |
| 관찰자 | 기록표에 결과·시간·발언을 적습니다. 진행에 끼어들지 않습니다. |
| 기기 | iPhone + Expo Go, 맥에서 `npx expo start` 실행. 앱은 EC2 HTTPS 서버에 연결합니다. |
| 테스트 계정 | 시연용 합성 계정(바탕화면 `시연계정_제출금지.txt`). 실제 개인정보는 입력하지 않습니다. |
| 데이터 초기화 | **참가자마다 시작 전에** `bash ~/Desktop/마감한칸_중간발표/_source/reset-demo-data.sh`를 실행합니다. 지연 1, 오늘 마감 1, D-2, D-5, D-6, 제출 완료 1이 만들어집니다. |
| 기타 | 인쇄한 기록표(참가자당 1부), 스톱워치, 필기구 |

처음 한 명은 팀원끼리 연습(파일럿)으로 해 보고, 시간과 문장을 조정합니다.

## 시작 안내 (그대로 읽기)

> 학교 모바일 SW 프로젝트에서 만들고 있는 과제 관리 앱 '마감한칸'을 확인하는 자리입니다. 약 25분 걸립니다.
> 오늘은 앱을 평가하는 것이지, 여러분을 평가하는 것이 아닙니다. 막히는 부분이 있다면 앱이 고쳐야 할 부분이니 편하게 해 주세요.
> 앱을 쓰는 동안 생각나는 것을 소리 내어 말해 주시면 큰 도움이 됩니다.
> 이름·학번·연락처는 기록하지 않고 'P1' 같은 코드로만 적습니다. 화면 녹화나 녹음은 동의하실 때만 합니다. 원하시면 언제든 중단할 수 있습니다.

동의 여부(진행 동의, 녹화·녹음)는 기록표 맨 위에 체크합니다.

## A. 인터뷰: 지금의 과제 관리 (8분, 앱을 보여 주기 전)

앱 이야기는 하지 않습니다. "이런 앱이 있으면 쓰겠어요?"처럼 답을 유도하는 질문은 하지 않습니다. 최근에 실제로 있었던 일을 묻습니다.

| 번호 | 질문 | 확인하려는 것 |
| --- | --- | --- |
| A1 | 이번 학기에 몇 과목을 듣고, 지금 진행 중인 과제는 몇 개쯤 있나요? | 워밍업 · 부담 정도 |
| A2 | 과제가 새로 생기면 보통 어디에, 어떻게 적어 두나요? 최근 과제 하나로 설명해 주세요. | 현재 도구(LMS, 캘린더, 메모, 안 적음) |
| A3 | 최근에 마감을 놓치거나 아슬아슬했던 적이 있나요? 그때 무슨 일이 있었는지 처음부터 말해 주세요. | 실제 실패 경험 · 원인 |
| A4 | 보고서나 팀 프로젝트처럼 큰 과제는 어떻게 시작하나요? 단계를 나누나요? 나눈다면 어디에 적나요? | H2 |
| A5 | 여러 과목 과제가 겹칠 때 무엇부터 할지 어떻게 정하나요? | 우선순위 기준 |
| A6 | 과제가 "얼마나 남았는지" 알고 싶을 때 무엇을 보거나 떠올리나요? | H1 |
| A7 | 마감 알림을 받는다면 언제 받는 게 가장 도움이 될까요? 지금 받는 알림이 있다면 도움이 되나요? | H3 |
| A8 | 지금 쓰는 방법에서 가장 불편한 점을 하나만 꼽는다면요? | 핵심 불편 |

되묻기 예: "예를 들면요?", "그때 어떻게 하셨어요?", "왜 그렇게 하세요?", "그 다음에는요?"

## B. 앱 사용 과제 (12분)

시연 계정으로 로그인한 홈 화면에서 시작합니다. 과제 문장은 그대로 읽어 주고, 화면 속 버튼 이름은 미리 말하지 않습니다. 참가자가 질문하면 "어떻게 하실 것 같아요?"라고 되묻습니다. 2분 넘게 막히면 힌트를 한 번 주고, 기록표에 '도움(A)'으로 적습니다.

| 번호 | 과제 문장 (그대로 읽기) | 성공 기준 | 관련 |
| --- | --- | --- | --- |
| B1 ★ | 이 화면을 보고, 지금 가장 먼저 처리해야 할 과제가 무엇인지 말해 주세요. 왜 그렇게 생각하셨어요? | '지연' 또는 '오늘 마감' 과제를 고르고 이유를 말함 | R05 |
| B2 ★ | '자료구조' 과목의 '연결 리스트 구현' 과제를 다음 주 금요일 밤 11시 59분 마감으로 등록해 주세요. | 저장 후 목록에 표시, 마감 일시가 맞음 | R01 |
| B3 ★ | 방금 등록한 과제를 '자료 조사', '코드 작성', '테스트' 세 단계로 나눠 적어 주세요. | 세부 작업 3개 추가 | R03 |
| B4 ★ | '자료 조사'를 끝냈다고 표시한 다음, 이 과제를 지금 얼마나 했는지 말해 주세요. | 체크하고 "33%" 또는 "3개 중 1개"라고 말함 | R04 |
| B5 | '모바일 SW' 과목 과제만 모아서 보세요. | 과목 필터 사용 | R05 |
| B6 | 'ERD 설계 과제' 마감이 하루 늦춰졌어요. 바꿔 주세요. | 수정 후 저장, 새 마감 표시 | R01 |
| B7 | '중간 발표 자료 준비'를 다 제출했다고 표시하고, 제출한 과제 목록에서 찾아 주세요. | 제출 완료 표시 → 제출 완료 탭에서 확인 | R06 |
| B8 | 마감 전에 알림을 받으려면 어디서 설정할지 찾아 주세요. | 홈 안내나 설정의 알림 항목을 찾음 | R07 |

★ 표시는 필수 과제(요구사항의 사용성 확인 흐름)입니다. 시간이 부족하면 B5–B8을 건너뜁니다.

각 과제가 끝나면 묻습니다: **"이 과제는 얼마나 쉬웠나요? 1(매우 어려움)부터 7(매우 쉬움) 사이로 답해 주세요."**

## C. 사후 질문 (5분)

| 번호 | 질문 |
| --- | --- |
| C1 | 써 보면서 가장 편했던 점과 가장 헷갈렸던 점은 무엇인가요? |
| C2 | 과제를 단계로 나누고 진행률(%)을 보는 것이 과제 관리에 도움이 될 것 같나요? 왜 그렇게 생각하세요? |
| C3 | 마감 하루 전 알림은 적절한 시점인가요? 다른 시점이 좋다면 언제인가요? |
| C4 | 지금 쓰는 방법 대신 이 앱을 쓸 의향은 1(전혀 없음)부터 5(매우 있음) 중 몇인가요? 이유는요? |
| C5 | 하나만 바꿀 수 있다면 무엇을 바꾸고 싶나요? |

마무리: 감사 인사. 데이터는 다음 참가자 전에 초기화합니다.

## 진행 시 주의

- 참가자가 틀린 버튼을 눌러도 바로 고쳐 주지 않습니다. 어디서 왜 헷갈렸는지가 가장 중요한 결과입니다.
- "좋아요", "맞아요"처럼 정답을 암시하는 반응을 하지 않습니다. "네, 계속해 주세요"로 통일합니다.
- 기능 요청은 그대로 받아 적되 약속하지 않습니다. 요청보다 그 뒤에 있는 불편(왜 필요한지)을 되물어 기록합니다.
- 화면에 서버 주소가 보이는 설정 화면은 녹화하지 않습니다.
