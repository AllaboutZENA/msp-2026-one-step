# 요구사항 — 초안 (2026-10-02 서버 구성 반영)

사용자: 여러 과목의 과제를 관리하는 대학생. 문제 가설: 마감일만 기록하면 남은 작업을 파악하기 어렵다. 3주차 사용자 확인 후 수정한다.

| ID | 요구사항 | 완료 기준 |
| --- | --- | --- |
| R01 | 과제 등록·수정·삭제 | 과목·제목·마감 검증, 변경 저장, 삭제 확인 |
| R02 | 서버 저장 | API를 거쳐 PostgreSQL에 저장, 앱 재실행 후 서버 데이터 조회; 네트워크·저장 실패 시 입력 유지와 안내 |
| R03 | 세부 작업 관리 | 추가·수정·삭제·완료 토글, 과제별 분리 |
| R04 | 진행률 | 작업 0개는 0%, 완료/전체 × 100을 반올림 |
| R05 | 마감 조회 | 미제출 과제 마감순 정렬, 지난 마감 지연 표시 |
| R06 | 제출 완료 | 별도 제출 완료·되돌리기, 완료 목록 분리 |
| R07 | 로컬 알림 | 기본 하루 전; 권한 거부·지난 예약·수정·삭제 처리. 기기 실험 후 확정. 서버 푸시는 범위 밖 |
| R08 | 사용자 인증·소유자 접근 | 본인 과제만 조회·수정·삭제; 다른 사용자 과제 ID 요청은 404. 인증 방식은 3–4주차 결정 |

홈, 등록·수정, 상세, 설정의 화면 4개를 사용한다. 입력은 수동이다. 데이터는 EC2의 API·PostgreSQL에 저장하며 최소 사용자 인증을 둔다. 학교 LMS 연동, AI 자동 계획, 채팅, 결제, 공동편집, 다중 기기 실시간 동기화, 앱스토어 출시는 이번 범위에 없다.

사용성 확인 계획: 학생 3~5명에게 ‘과제 등록 → 세부 작업 3개 추가 → 1개 완료 → 마감 확인’을 수행하도록 하고 완료 여부·소요 시간·혼동 지점을 기록한다. 관찰 결과를 개선의 근거로 사용한다.
